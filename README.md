# Wake Mini 1.5.4

## Текущая сборка

Windows-помощник 1.5.4.0 и облачная функция 1.5.4. Android не менялся. Режим «Кино» удалён. «Работа» и «Игры» переключают окна; команда «Разговор с ChatGPT» автоматически запускает Chrome, подключает наушники и включает голос через расширение.

[Инструкция и порядок обновления 1.5.4](docs/UPDATE-1.5.4.md).


Компактная Android-утилита для Wake-on-LAN с круглой кнопкой-виджетом на главном экране. Нажатие на виджет само выполняет переключение: если Windows-помощник доступен, отправляет защищённую команду выключения; если ответа нет, отправляет magic packet для включения.

## Сборка Android-приложения

Версия 1.1.3 показывает индикатор связи: зелёный, если Windows-помощник отвечает, красный, если ответа нет. Проверка идёт при открытом приложении раз в 15 секунд и по нажатию «Проверить». Настройки сохраняются автоматически на телефоне.

Откройте папку `WakeMini` в Android Studio с Android SDK Platform 35 и выполните **Build > Build APK(s)**. Сторонние Android-библиотеки не используются.

## Настройка компьютера и роутера

1. Подключите ПК к роутеру кабелем Ethernet. Включите Wake-on-LAN в BIOS/UEFI и в свойствах сетевого адаптера Windows.
2. На Archer AX1800 закрепите за ПК постоянный IP. В правилах перенаправления UDP-порта направьте порт `3000` на этот IP. Внешний адрес/DDNS и порт `3000` используйте в приложении.
3. Скачайте `WakeMiniAgent.exe` из GitHub Release и положите его в отдельную папку, например `C:\\WakeMini`.
4. Один раз запустите `Allow-WakeMini-Firewall.bat` и подтвердите запрос Брандмауэра Windows. Это разрешает входящие UDP-пакеты помощнику на порту `3000`.
5. Запустите `WakeMiniAgent.exe`. При первом запуске он создаст рядом файл `wake.key` и покажет 64-символьный ключ. Введите этот ключ в Wake Mini на телефоне. Не передавайте ключ другим людям.
6. Для автозапуска помощника создайте ярлык `WakeMiniAgent.exe` в папке автозагрузки Windows: нажмите Win+R, введите `shell:startup` и поместите туда ярлык. Новая версия запускается сразу в области уведомлений рядом с часами.
7. Щёлкните правой кнопкой по значку Wake Mini в трее → **Настроить приложение**. Выберите файл `.exe`. Можно добавить параметры запуска и включить запуск приложения при входе в Windows.
8. В приложении укажите MAC проводного адаптера ПК, DDNS-имя роутера, UDP-порт `3000` и ключ. Затем добавьте виджет Wake Mini на главный экран телефона.

## Поведение кнопки

- Если помощник отвечает с правильным ключом, приложение просит Windows выключить ПК через 10 секунд.
- Если ответа нет, приложение отправляет Wake-on-LAN пакет. Это сработает, когда ПК выключен или спит, а роутер и сетевой адаптер настроены на WoL.
- Если помощник остановлен или порт закрыт, включение может сработать, а выключение — нет. Для переключения помощник должен быть запущен на ПК.

Помощник принимает только проверку состояния и команду выключения с HMAC-подписью и одноразовым запросом. Он не выполняет произвольные команды. Если провайдер использует CGNAT, проброс порта извне может быть недоступен.

## Управление через Алису без Home Assistant

Приватный навык «Умный дом» управляет компьютером через Yandex Cloud: включение, выключение, перезагрузка, сон и запуск выбранного приложения. Windows-помощник запускается в трее; выбранное приложение можно запускать при входе в Windows. APK Android обновлять не нужно.

В «Доме с Алисой» можно создать голосовой сценарий, который включает ПК. Если в настройках Wake Mini включён автозапуск выбранного приложения, оно откроется после загрузки Windows.

[Инструкция по обновлению облачной функции и помощника](alice-cloud/README.md).


## Обновление 1.3.0

- Android: QR-подключение из Windows, отдельные кнопки включения/выключения, диагностика DDNS/ключа/сети, история последних команд без секретов, профили Работа/Игры, новая иконка. Круглая кнопка и виджет сохранены.
- Windows: автозагрузка помощника через меню трея, QR-код подключения, окно диагностики, настройка профилей Работа/Игры, отмена выключения и защита от запуска второй копии.
- Протокол: повторяется тот же подписанный пакет с тем же nonce и UDP-портом. Помощник повторно отправляет сохранённое подтверждение в течение 30 секунд, не выполняя действие снова. Для старого помощника повтор безопасен, но восстановление потерянного подтверждения требует версии 1.3.0.

### Настройка новых возможностей

1. Выйдите из старого помощника через трей, замените EXE. Сохраните `wake.key` и `wake-actions.json`.
2. В меню трея включите «Запускать помощник вместе с Windows». Старый ярлык можно удалить; если он останется, вторая копия завершится без повторного запуска программы.
3. Откройте «Подключить телефон / QR», укажите DDNS и проверьте MAC проводного адаптера, нажмите «Сохранить и показать QR-код».
4. В Android нажмите «Настроить по QR-коду с ПК», разрешите доступ к камере и подтвердите адрес. QR содержит секретный ключ — не публикуйте его.
5. В Windows откройте «Профили: Работа / Игры», выберите EXE и параметры каждого профиля. Пустые профили ничего не запускают. Пути задаются только локально; сеть не может передать произвольную программу.
6. Для текущей версии используйте облачную функцию `WakeMini-Alice-Cloud-1.5.4.zip`. Сохраните переменные окружения и обновите список устройств навыка. Полная инструкция находится в [документе обновления 1.5.4](docs/UPDATE-1.5.4.md).
7. Профили требуют уже работающей Windows. Для выключенного ПК сначала включите компьютер и дождитесь входа в Windows. Прежний автозапуск выбранного приложения при входе сохранён.

### Постоянная подпись Android — один раз

Раньше релизы собирались как Debug на новых GitHub runners. Ключ тех сборок не сохранён: гарантировать установку поверх старой версии нельзя. Новый ключ нельзя восстановить из APK. До настройки секретов сборка проверяется, но новый устанавливаемый APK не публикуется — случайные временные ключи больше не используются для релизов.

1. На своём Windows ПК установите GitHub CLI: `winget install --id GitHub.cli --exact`. Нужен Java JDK или установленная Android Studio.
2. Скачайте `Setup-WakeMini-Signing.ps1` из релиза и выполните в PowerShell: `powershell -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Setup-WakeMini-Signing.ps1"`.
3. Скрипт предложит войти в GitHub через браузер, создаст постоянный JKS в `%LOCALAPPDATA%\WakeMiniSigning`, сохранит его и пароль в GitHub Actions Secrets и запустит выпуск. Пароль не выводится; локально он защищён Windows DPAPI. Существующий JKS не перезаписывается.
4. После успешного Actions в релизе 1.3.0 появится `WakeMini-1.3.0.apk`. Все следующие релизы используют тот же ключ. Не удаляйте и не заменяйте GitHub Secrets и локальную папку ключа.
5. Если Android отклонит обновление старой Debug-версии из-за подписи, настройте QR в Windows, затем удалите старое Android-приложение, установите 1.3.0 и восстановите параметры сканированием QR. Это однократный переход, а не требование будущих обновлений.

Скрипт устанавливает четыре секрета: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. Для настройки вручную создайте те же repository secrets. Ключ/пароли не отправляйте в чат и не коммитьте.


## LG OLED / webOS — обновление 1.4.0

Windows-помощник напрямую управляет LG по локальной сети. Дополнительная программа LGTV Companion не нужна; если она установлена, отключите в ней автоматическое управление этим телевизором, чтобы действия не дублировались.

### Первое подключение LG C5

1. Сохраните прежние `wake.key` и `wake-actions.json`, завершите помощник через трей и замените EXE. Настройки телефона, роутера, Алисы и прежние команды ПК сохраняются.
2. Подключите телевизор и ПК к одной локальной сети. Закрепите IP телевизора в DHCP роутера. На ТВ включите «TV On With Mobile / Включение ТВ с мобильного» → «Включение через Wi-Fi» даже при Ethernet. Названия пунктов зависят от прошивки. ТВ остаётся в розетке.
3. В меню трея Wake Mini откройте **Телевизор LG OLED…**. Укажите локальный IPv4, MAC используемого подключения ТВ и HDMI компьютера (1–4). Для C5 оставьте WSS/3001 включённым. Обычный WS/3000 — только явная настройка для моделей, где WSS недоступен.
4. Включите ТВ с пульта, нажмите **Сохранить и выполнить сопряжение с ТВ** и подтвердите разрешение на экране ТВ в течение 60 секунд. Переключение источника при сопряжении не выполняется.
5. Нажмите **Включить ТВ / переключить на ПК**. Дождитесь подтверждения HDMI в окне диагностики помощника. Если ТВ выключен, помощник отправляет WoL, ограниченно повторяет подключение и выбирает HDMI после ответа webOS. Результат означает подтверждение API, а не визуальную проверку изображения.
6. Если требуется включение ТВ при каждом запуске помощника, включите соответствующую галочку и автозагрузку самого помощника. **Это запуск при входе пользователя в Windows; до экрана входа помощник не работает. Ручной запуск помощника тоже запускает это действие.** По умолчанию галочка выключена.

### Два варианта использования

- **Всегда вместе:** включите автовключение ТВ в помощнике. Оно сработает после обычного старта, перезагрузки, а также после удалённого запуска при входе в Windows. Помощник не отличает кнопку корпуса от WoL. Пробуждение Windows из сна не перезапускает помощник; используйте кнопку ТВ на телефоне или в трее.
- **ПК отдельно или вместе с ТВ:** оставьте автовключение ТВ выключенным. Прежние «Включить ПК», виджет и Алиса включают только ПК. Новая Android-кнопка **Включить ПК + телевизор LG** отправляет WoL при недоступном помощнике, ждёт его запуска до 2 минут, затем отправляет защищённый запрос ТВ и ждёт результата до 70 секунд. Держите приложение открытым; если требуется пароль Windows, войдите в свою учётную запись. Для уже работающего ПК используйте **Переключить LG на ПК**.

**Остановить попытки включения ТВ** отменяет ожидание на телефоне и посылает отмену помощнику, если он доступен. Уже выполненное включение/переключение не откатывается. Если телефон не получил подтверждение, действие могло выполниться — проверьте ТВ и диагностику. При закрытии Android ожидание прекращается; команда, уже принятая Windows, может завершиться самостоятельно.

Выключение ПК не выключает телевизор. Простой, блокировка и выключение монитора Windows не управляют ТВ. Постоянного опроса телевизора нет: до 65 секунд на одно действие и затем соединение закрывается. Не включайте отдельное автоматическое управление этим же ТВ в других программах.

### Протокол и хранение

Добавлены подписанные команды `TV_PC`, `TV_STATUS`, `TV_CANCEL` с тем же HMAC, одноразовым запросом и защитой повторов. `TV_PC_ACCEPTED` означает принятие фоновой задачи; фактическое подтверждение HDMI проверяется отдельной командой статуса. Старый помощник эти команды игнорирует, поэтому обновите EXE перед использованием новых кнопок. Старые команды ПК работают как раньше. Облачная функция Алисы не менялась: голосовое включение ПК сохраняется; нового голосового устройства ТВ в этой версии нет.

Параметры и ключ webOS сохраняются отдельно в `wake-tv.json` рядом с EXE. Файл содержит секрет сопряжения в открытом виде, как локальные ключи текущего помощника: не публикуйте его и храните папку под своей учётной записью Windows. При WSS после одобренного сопряжения сохраняется SHA-256 сертификата ТВ; следующие соединения принимают только этот сертификат. После его смены прошивкой требуется повторное сопряжение. IP/команды ТВ нельзя передать с телефона: они задаются только локально.

Проверки: `dotnet run --project tests/tv/TvTests.csproj` проверяет реальный TLS/WebSocket обмен с имитатором ТВ, WoL-пакет, выбор HDMI, сохранение ключа, отрицательный ответ и запрет незапрошенного повторного сопряжения. Это не заменяет проверку на физическом LG C5.

Справка по использованному SSAP: [lgtv2](https://github.com/hobbyquaker/lgtv2), [LGTV Companion](https://github.com/JPersson77/LGTVCompanion).


## Исправление LG — 1.4.1

В 1.4.0 разные отказы LG скрывались за одной общей ошибкой. По старому сообщению нельзя определить, был ли это отказ регистрации, недостаток разрешений или неподдерживаемый метод HDMI.

- Диагностика теперь показывает этап (`сопряжение / регистрация`, `tv/switchInput`, `system.launcher/launch`) и числовой код LG, не записывая регистрационный ключ.
- Явное повторное сопряжение запрашивает обновлённые разрешения: CONTROL_INPUT_TV, READ_INPUT_DEVICE_LIST, LAUNCH. Устаревшие подписанные тестовые манифесты LG не используются.
- При отказе 401/403/404 старого метода выбора HDMI выполняется одна попытка выбрать тот же фиксированный вход через system.launcher/launch. Произвольные приложения ТВ запускать через сеть нельзя.
- Если запускающаяся webOS закрывает уже установленное соединение, помощник ограниченно повторяет подключение. Отказы авторизации не вызывают автоматического сопряжения. Смена сертификата показывается отдельно.
- Результат команды теперь появляется прямо в открытом окне настроек телевизора.

### Обновление

1. Завершите помощник через трей и замените WakeMiniAgent.exe версией 1.4.1. Сохраните wake.key, wake-actions.json и wake-tv.json рядом с EXE.
2. Включите LG с пульта. Откройте «Телевизор LG OLED…», проверьте IP/MAC/HDMI и WSS/3001.
3. Нажмите «Сохранить и выполнить повторное сопряжение с ТВ…» и подтвердите новый запрос на экране телевизора. Это нужно, чтобы LG предоставил добавленное разрешение LAUNCH.
4. Нажмите «Включить ТВ / переключить на ПК». При повторном отказе скопируйте свежую диагностику с этапом и кодом.

Для этого исправления достаточно обновить Windows-помощник. Android 1.4.0 совместим, облачную функцию Алисы обновлять не требуется. Android 1.4.1 в релизе подписан тем же постоянным ключом.

Тесты проверяют TLS, сохранённый ключ, разрешения регистрации, 404 → резервный HDMI launcher, отказ 401 на регистрации, отказ launcher, отсутствие ключа в диагностике и восстановление после закрытия соединения. Проверка физического LG C5 остаётся необходимой.
