# Wake Mini — компьютер в Доме с Алисой

Облачный обработчик без Home Assistant и без дополнительного постоянно работающего устройства дома. Требуются включённый роутер, питание сетевого адаптера выключенного ПК и уже работающий Wake-on-LAN из внешней сети.

**Релиз 1.1.0:** к включению и выключению добавлены отдельные действия перезагрузки и спящего режима, а также запрос состояния Windows-помощника. Для новых команд нужны обновлённая облачная функция и новый `WakeMiniAgent.exe`; APK Android обновлять не нужно. Перед развёртыванием сохраните настройки окружения функции.

Компьютер имеет тип `devices.types.other`, а не выключатель света.

## Что делают команды

- «Алиса, включи компьютер» — три одинаковых WoL-пакета на настроенный DDNS/UDP-порт. Успешный ответ означает отправку пакетов, а не подтверждённую загрузку Windows.
- «Алиса, выключи компьютер» — проверка подписи помощника, команда завершения работы и проверка подтверждения.
- «Алиса, включи перезагрузку компьютера» — одноразовая команда Windows `shutdown.exe /r /t 10`.
- «Алиса, включи спящий режим компьютера» — одноразовый вызов штатной функции Windows для перехода в сон.
- Запрос состояния отвечает «включён» только если Windows-помощник ответил на подписанный UDP-запрос. Если ответа нет, Алиса сообщает, что устройство недоступно: по сети нельзя отличить выключенный или спящий ПК от проблем с маршрутом. Этот запрос ничего не включает и не выключает.
- Перезагрузка и сон опубликованы как одноразовые устройства с действием только «включить». Команда «выключить» для них отклоняется.

## 1. Проверка сети

Отключите Wi-Fi на телефоне и проверьте включение ПК в Wake Mini через мобильный интернет. Облачный обработчик будет использовать тот же путь. Для существующей настройки используйте `magral.tplinkdns.com`, порт `3000` и MAC вашего проводного адаптера. Роутер должен сохранять привязку IP/MAC, DHCP-резервирование и проброс UDP-порта. При CGNAT без входящего доступа этот вариант не заработает.

Выключение требует запущенного `WakeMiniAgent.exe` из релиза 1.1.1, разрешения UDP 3000 в Брандмауэре Windows и автозагрузки помощника.

## 2. Авторизация через Яндекс ID

1. На https://oauth.yandex.ru/ создайте приложение для неофициального приватного навыка. Выберите веб-платформу и доступ к информации о пользователе (`login:info`).
2. Redirect URI: `https://social.yandex.net/broker/redirect`.
3. Сохраните **Client ID** и **Client secret**. Не публикуйте secret в репозитории и не отправляйте ключи в чат.

## 3. Облачная функция

1. Откройте https://console.yandex.cloud/ и выберите каталог. Если потребуется создать платёжный аккаунт или принять условия, выполните это самостоятельно. Проверьте тарификацию: https://yandex.cloud/ru/docs/functions/pricing .
2. Создайте функцию `wakemini-alice` в Cloud Functions.
3. Создайте версию: Python 3.12, память 128 МБ, точка входа `main.handler`, таймаут 3 секунды, ZIP `WakeMini-Alice-Cloud-1.1.0.zip` из [релиза 1.1.0](https://github.com/Magral/wakeup/releases/tag/alice-cloud-v1.1.0). Сохраните имеющиеся переменные окружения при создании новой версии.
4. Добавьте переменные окружения:

| Имя | Значение |
| --- | --- |
| `PC_HOST` | Ваш DDNS, например `magral.tplinkdns.com` |
| `PC_MAC` | MAC проводного адаптера ПК |
| `PC_PORT` | `3000` |
| `AGENT_KEY` | Содержимое `wake.key` рядом с помощником — 64 hex-символа |
| `YANDEX_LOGIN` | Логин аккаунта, к которому привязываете компьютер, без `@yandex.ru` |
| `OAUTH_CLIENT_ID` | Client ID приложения из шага 2 |

5. Создайте версию. Для вызовов от Диалогов функции нужен доступ на вызов. При использовании публичного вызова доступ к командам всё равно ограничивается проверкой действительного OAuth-токена, совпадением логина и Client ID. Включайте публичный вызов только у этой функции, не у других ресурсов.
6. Скопируйте ID функции.

Ключ помощника нужен облачному обработчику для подписи команд. Он хранится в конфигурации Yandex Cloud, не в ZIP, не в URL и не в GitHub. Доступ к настройкам функции предоставляйте только своему аккаунту.

## 4. Приватный навык умного дома

1. https://dialogs.yandex.ru/developer/ → Создать диалог → **Умный дом** (не обычный разговорный навык).
2. Название: `Wake Mini`. Тип доступа: **Приватный**. Официальный навык: **Нет**.
3. Backend: **Функция Yandex Cloud** → ID из шага 3. Не указывайте HTTP Endpoint вместо этого варианта.
4. Для описания подключения укажите: «Привяжите свой аккаунт Яндекса. В списке появится устройство Компьютер». Иконку можно выбрать собственную.
5. Вкладка «Связка аккаунтов»:

| Поле | Значение |
| --- | --- |
| Идентификатор приложения | Client ID |
| Секрет приложения | Client secret |
| URL авторизации | `https://oauth.yandex.ru/authorize` |
| URL получения токена | `https://oauth.yandex.ru/token` |
| URL обновления токена | `https://oauth.yandex.ru/token` |
| Идентификатор группы действий | `login:info` |

6. Сохраните и опубликуйте приватный навык. Если консоль попросит дополнительные поля или проверку, выполните указания консоли.
7. В «Доме с Алисой» под тем же аккаунтом: `+` → Устройство умного дома → найдите свой приватный навык → Привязать к Яндексу.
8. Обновите список устройств. Должен появиться **Компьютер**. Добавьте его в комнату и проверьте включение и выключение кнопками, затем голосом на колонке с этим аккаунтом.

## Обновление с версии 1.0.1

1. Скачайте ZIP облачной функции и `WakeMiniAgent.exe` из [релиза 1.1.0](https://github.com/Magral/wakeup/releases/tag/alice-cloud-v1.1.0).
2. В Yandex Cloud создайте новую версию `wakemini-alice` из ZIP. Проверьте, что в новой версии сохранены все шесть переменных окружения из раздела 3.
3. На ПК остановите старый помощник, замените `WakeMiniAgent.exe`, сохраните рядом существующий `wake.key` и запустите новую версию. Создавать новый ключ или повторно настраивать проброс UDP-порта не нужно.
4. В Доме с Алисой обновите список устройств навыка. Добавьте новые устройства **Перезагрузка компьютера** и **Спящий режим компьютера** в комнату «Кабинет».
5. Проверьте команды сначала кнопками в приложении, затем голосом. Команды перезагрузки и выключения закрывают сеанс Windows; сохраните документы заранее. Перезагрузка запланирована через 10 секунд.

## Ограничения и проверка

- Вся обработка запроса умного дома должна уложиться в 3 секунды. Заложены таймауты 0,8 с для Яндекс ID и по 0,6 с для двух UDP-ответов; DNS, холодный запуск и доставка также занимают время. До проверки в реальной сети нельзя обещать отсутствие таймаутов.
- При неверной авторизации обработчик ничего не отправляет на ПК. Нативный raw-вызов Cloud Functions не позволяет выставить HTTP 401; в этом случае обработчик завершится безопасной ошибкой, а Алиса может сообщить общую ошибку подключения. HTTP-обёртка для тестов возвращает 401.
- Нет подтверждения выключения, перезагрузки или сна — возвращается ошибка, без повторной команды и без WoL. Команда могла быть принята, а её подтверждение потеряно.
- Помощник 1.1.1 использует штатный Windows `shutdown.exe /s /t 10`; завершите работу с несохранёнными документами перед проверкой.
- Обработчик поддерживает один компьютер и один разрешённый аккаунт. Помощник принимает только подписанные команды `STATUS`, `SHUTDOWN`, `RESTART` и `SLEEP`, не меняет настройки сети и не выполняет произвольные команды.

## Проверка исходников

Из корня репозитория:

```sh
python3 -m unittest discover -s alice-cloud/tests -v
```

Тесты используют только локальный UDP-имитатор. Настоящий ПК не выключается.
